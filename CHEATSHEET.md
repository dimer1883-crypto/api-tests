# Шпаргалка: как самому написать API-тест

Держать под рукой, когда «не понимаю, какой код писать». Здесь только порядок
действий, без магии.

---

## 1. От доки до теста — шесть шагов

1. Найти операцию в документации: метод и путь (`GET /users/{id}`).
2. Понять, что на входе: обязательные поля, есть ли параметры адреса, нужен ли токен.
3. Сделать один живой запрос и посмотреть реальный ответ: код статуса и тело.
4. Выписать утверждения из этого ответа: что там обязано быть всегда.
5. Написать тест: имя → фикстуры → один запрос → утверждения.
6. Добавить негативные проверки: без токена, несуществующий id, битые данные.

Утверждения не придумываются. Их списывают с ответа сервера: тест фиксирует контракт,
то есть то, что сервер пообещал возвращать.

## 2. Скелет, из которого растёт любой тест

```python
def test_что_делаем(фикстуры):
    response = requests.get(f"{base_url}/путь", params={"ключ": "значение"})

    assert response.status_code == 200
    assert response.json()["поле"] == "значение"
```

| Часть | Что туда идёт |
|---|---|
| имя `test_...` | бизнес-смысл: «товар из категории отдаётся в каталоге» |
| фикстуры | что нужно до теста: адрес стенда, токен, созданный объект |
| строка с `requests` | ровно один запрос: метод, адрес, параметры или тело |
| `assert` | 2–4 проверки кода и тела |

## 3. Методы и коды ответов

| Метод | Смысл | Обычный код успеха |
|---|---|---|
| GET | прочитать | 200 |
| POST | создать | 200 или 201 |
| PUT | заменить объект целиком | 200 |
| PATCH | изменить только переданные поля | 200 |
| DELETE | удалить | 200, 201 или 204 |

Токен нужен там, где меняются данные: PUT, PATCH, DELETE (и иногда POST).
Чтение чаще всего открыто.

Проверять надо и негатив: без токена обычно 401 или 403, несуществующий id — 404,
битые данные — 400 (у FastAPI 422).

---

## 4. Где взять готовый запрос

- Swagger (FastAPI-стенды, страница `/docs`): раскрыть операцию → `Try it out` → ввести
  параметры → `Execute`. Показывает и запрос, и ответ.
- Postman: `New` → `HTTP Request` → метод + URL → `Body` → `raw` → `JSON` → вставить тело
  → `Send`. Затем кнопка `Code` (значок `</>`) → `Python - requests` → готовый код запроса.
- Браузер, если доки нет: `F12` → `Network` → сделать действие на странице → правый клик
  по запросу → `Copy` → `Copy as cURL`. Дальше конвертер cURL → Python.
- Терминал: `curl -s -X POST "<url>" -H "Content-Type: application/json" -d '<тело>'`.

Переменные Postman `{{base_url}}` в коде становятся фикстурой `base_url` — адрес стенда
меняется в одном месте.

## 5. Как превратить сниппет Postman в тест

Postman отдаёт такое:

```python
import requests

url = "https://example.com/booking"
payload = "{\n    \"firstname\" : \"Dmitry\"\n}"
headers = {'Content-Type': 'application/json'}

response = requests.request("POST", url, headers=headers, data=payload)
print(response.text)
```

Что выкинуть:

| Из Postman | Почему |
|---|---|
| `print(response.text)` | результат проверяют assert'ы, а не печать |
| `headers={'Content-Type': ...}` | `requests` ставит заголовок сам, когда передаёшь `json=payload` |
| `requests.request("POST", ...)` | есть короткие формы `requests.post(...)`, `requests.get(...)` |
| payload строкой с `\n` | словарь читается и правится без боли |

Что добавить: имя теста, фикстуры и утверждения. Итог:

```python
def test_create_booking(booking_url):
    payload = {
        "firstname": "Dmitry",
        "lastname": "Erakhtin",
        "totalprice": 150,
        "depositpaid": True,
    }

    response = requests.post(f"{booking_url}/booking", json=payload)

    assert response.status_code == 200
    assert response.json()["bookingid"] > 0
```

## 6. Грабли, на которых спотыкаются все

- Тело уходит как текст, а не как JSON. Признак: `400 Bad Request` при внешне правильном
  теле. В Postman включай `Body → raw → JSON` и следи, чтобы не было красного подчёркивания.
  В Python всегда `json=payload`, а не `data=payload`.
- Кириллица с русской раскладки внутри английских слов (`о` вместо `o`, `с` вместо `c`,
  `а` вместо `a`) — выглядит одинаково, а JSON или поле считается другим. Проверка:
  в VSCode `Ctrl+F` → включить регулярные выражения → искать `[^\x00-\x7F]`.
- Хрупкие проверки: точное число, которое может измениться (количество товаров), лучше
  проверять как «больше нуля», а не «равно 120». Иначе тест упадёт сам по себе.
- Проверять надо и негатив: без токена обычно 401 или 403, несуществующий id — 404,
  битые данные — 400 (у FastAPI 422).
- Токен живёт ограниченное время. Если посреди прогона пошли 403 — сначала подозревай это.
- Тест обязан убирать за собой: создал объект — удали его в фикстуре после теста.
- Проверяй состояние на сервере, а не ответ на изменение: после PUT сделай GET и сверь.
